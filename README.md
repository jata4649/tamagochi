# ふれんどっち(たまごっち風育成 Web アプリ)

ブラウザだけで遊べる、たまごっち風のペット育成アプリです。
HTML + CSS + Vanilla JS の静的サイトで、ビルドツールやフレームワークは使いません。
スマホ縦持ち優先(375px〜)、PC では中央に最大 480px のカードで表示します。

## 遊び方

1. タイトル画面で色(きいろ / みどり / ピンク)を選び、「たまごをもらう」を押す
2. たまごは 約1分で孵化(育つはやさ「はやい」のとき)。孵化したら名前をつける(空なら「ふれんどくん」)
   - 孵化すると、半分の確率で選んだ色のまま、半分の確率で新しい種族(ネコ・モモンガ・うさぎ・アザラシのどれか)が生まれます
3. 下の8つのボタンでお世話をする

| ボタン | すること |
|---|---|
| ごはん | 12種から選んで食べる(おなか +25・きげん +3、水・ジュースは おなか +3・げんき +5)。病気中は効果半分 |
| おやつ | おなか +8・きげん +15。2時間に3回まで(超えると きげん が下がる) |
| 遊び | 4つのミニゲームから選んで遊ぶ(下の「ミニゲーム」)。病気中は遊べない |
| おふろ | せいけつ を満タンに |
| トイレ | 床のうんちを片付ける |
| くすり | 病気を治す(病気でないのに飲ませると きげん が下がる) |
| おやすみ | 寝かせる/起こす。寝ている間は げんき が回復し、他のボタンは使えない |
| じょうたい | ゲージの数値・年齢・ミニゲームの記録を見る |

- ゲージ(おなか・きげん・せいけつ・げんき)は時間とともに減ります。どれかが 30 未満、病気、うんちがあるときは左上の「!」が点滅します。
- ごはんの 5〜13分後にうんちが出ます。放っておくと病気になることがあります。おなか 0 が 20分続いても病気になります。
- ベビー → こども(1時間)→ おとな(さらに 2時間)と育ちます(「はやい」のとき)。
- おなか 0 が 40分、または きげん 0 が 8時間続くと、お別れになります。「あたらしいたまご」で最初から遊べます。
- アプリを閉じている間も時間は進みます(最大 24時間分)。寝かせたまま閉じると、寝たまま時間が進みます。
- 右上の歯車で「せってい」を開けます。
  - みどり・ピンクの ひょうじょう: オンにすると、きいろの表情の絵を色を変えて使う(既定オン)
  - おと: 簡単な効果音(既定オフ)
  - そだつ はやさ: はやい(デモ)/ ふつう(たまご 20分・ベビー 8時間・こども 16時間)
- ここに書いた時間はすべて進行速度 `PACE=3`(3倍速)のときの値です(下の「仕様メモ → 進行速度」)。

## ミニゲーム

「遊び」を押すとゲームセレクト(4つ)が開きます。タイルには各ゲームの「いちばん」(最高スコア)が出ます。

| ゲーム | 遊び方 | きげん |
|---|---|---|
| ボールあて | 公園でボールが左右に動いたあと、どっちに飛ぶか「ひだり / みぎ」で当てる。3ラウンド | あたり +12 / はずれ −4 |
| ハイアンドロー | 表のカードより次のカードが強いか弱いかを「たかい / ひくい」で当てる。5回勝負。強さは き < くも < ひこうき < たいよう < ほし < つき | +(当たった数 × 2)、最大 +12。全問正解で大きな星 |
| もぐらたたき | 20秒間、3×3 の巣穴から出てくるもぐらをタップ。時間がたつほど同時に出る数が増え、残り10秒から速くなる | +(スコア ÷ 2)、最大 +12 |
| おんぷキャッチ | 30秒間、かごを「ひだり / みぎ」ボタン・タップ(PC は ← →)で3か所に動かし、落ちてくるものを受ける。おんぷ +1・ほし +3・うんち −2(かごが震える) | +スコア、最大 +12 |

共通のルール:

- 1回遊ぶと げんき −5。げんきが 5 より少ないと遊べない(「げんきが 足りないよ」)
- 1回で きげん が動くのは最大 +15 / −8 まで
- 遊び終わると同じゲームは1分休憩(タイルが薄くなり、結果画面の「もう一回」も押せない)。休憩はアプリを開いている間だけの記録で、リロードすると解除される
- 結果画面に「スコア」「いちばん」が出て、記録を更新すると「きろく更新!」
- 遊んでいる途中は左上の「もどる」でやめられる(げんきは戻らず、記録も付かない)
- 病気中・寝ている間は遊べない。遊んでいる途中で別のアプリに切り替えると、ゲームの時間は止まる

## ローカルで起動する

`file://` で直接開くと `fetch` が失敗することがあるため、必ずローカルサーバ経由で開きます。

```sh
python3 -m http.server 8000
# ブラウザで http://localhost:8000/ を開く
```

## GitHub Pages で公開する

1. このリポジトリを GitHub に push する(`index.html` がリポジトリ直下にある状態)
2. GitHub のリポジトリ画面で **Settings → Pages** を開く
3. **Build and deployment** の Source を「Deploy from a branch」にし、Branch で公開するブランチと `/ (root)` を選んで Save
4. 数分後に表示される `https://<ユーザー名>.github.io/<リポジトリ名>/` を開けば誰でも遊べます

Netlify の場合は、リポジトリ(またはフォルダ)をそのまま登録し、ビルドコマンドなし・公開ディレクトリはルートにします。

## セーブデータの消し方

- ゲーム内: お別れ画面の「あたらしいたまご」でセーブが消えます。
- 手動: ブラウザの DevTools を開き、**Application(Safari は「ストレージ」)→ Local Storage** でこのサイトの `tt_save_v1`(ゲーム)と `tt_settings_v1`(せってい)を削除します。コンソールで `localStorage.removeItem('tt_save_v1')` を実行してリロードしても消せます。
- ミニゲームの成績(各ゲームの「いちばん」と遊んだ回数)は `tt_save_v1` の中の `games` に入っています。セーブを消すと成績も消えます。成績だけを消したいときは、コンソールで次を実行してリロードします:
  `const s = JSON.parse(localStorage.getItem('tt_save_v1')); delete s.games; localStorage.setItem('tt_save_v1', JSON.stringify(s));`
- セーブの形式は `"version": 2` です。ミニゲーム追加前の `version: 1` のセーブは、読み込んだときに自動で引き継がれます。

## 開発者向け(DevTools のコンソール)

- `tt.state` … セーブデータ本体(書き換えると約1秒で画面に反映)
- `tt.state.stageEnteredAt -= 3 * 3600e3` … 段階の経過時間を3時間進める(進化の確認)
- `tt.away(3)` … 3時間離れていたことにしてリロードする(オフライン補正の確認)
- `tt.clearCooldowns()` … ミニゲームの休憩を解除する
- `tt.PACE` … 今の進行速度。`http://localhost:8000/?pace=2` のように URL で開くと、その間だけ進行速度を変えて試せる(保存はしない)
- `tt.gameDebug.live` … ミニゲームのタイマー・リスナーが今いくつ動いているか(ゲームを抜けると 0)

## ファイル構成

```
index.html        … 1ページだけ。画面はこの中で切り替える
css/style.css     … デザイン全部(色などの変数は :root)
js/main.js        … 初期化・ゲームループの入口
js/state.js       … セーブデータの形・ゲージ更新・状態判定・スプライト選択
js/lifecycle.js   … 孵化・進化・お別れの判定と TIME_SCALE
js/screens.js     … 全画面(タイトル・名前入力・お別れ)
js/actions.js     … 8つのボタンアクションの処理・食材データ
js/overlays.js    … オーバーレイ画面(食事選択・ステータス)
js/games/select.js … ゲームセレクト(遊びボタンの入口・4タイル)
js/games/common.js … ミニゲーム共通(タイマー等の一括解除・開始条件・報酬の上限・休憩)
js/games/result.js … 共通の結果画面
js/games/ball.js  … ボールあて(元の「ボールの飛ぶ方向当て」)
js/games/hilo.js  … ハイアンドロー
js/games/mole.js  … もぐらたたき
js/games/catch.js … おんぷキャッチ
js/economy.js     … ドッチ(通貨)の値段・アルバイト代・増減(COIN_RATE で1か所管理)
js/shop.js        … おみせ(上部バーのチップ・売り物・購入)
js/ui.js          … 画面描画・トースト
js/effects.js     … 演出(zzz・うんち・B/C の補助表示など)
js/settings.js    … せってい画面と設定の保存(tt_settings_v1)
js/sound.js       … WebAudio の簡易ビープ
js/save.js        … localStorage の読み書き・型の補正
js/assets.js      … manifest 読み込み・assetPath・素材パス定数
js/strings.js     … UI 文言辞書(画面の文字列はすべてここ)
assets/           … 素材 ZIP の展開物(読み込み専用・編集禁止)
```

### 進行速度(調整パッチ「tamagotchi_pace_tuneup_spec_claude.md」)

**進行速度: PACE=3(2026-10 調整)**

上の仕様メモに書いた時間(15〜40分、3時間 など)は、元の仕様書の「1倍速」の値です。実際の時間はすべて `js/state.js` の `PACE` から計算しています。速さを変えたいときは `PACE` の値だけを変えます(3 = 3倍速、2 = 2倍速、1 = 元の仕様書どおり)。

| # | 内容 | 決定 |
|---|---|---|
| P1 | PACE の置き場所 | `js/state.js` の冒頭に `export const PACE`(既定 3)。§0 には「TIME_SCALE と同じ場所」とあるが、TIME_SCALE は `js/lifecycle.js` にあり、ファイル構成は変えないことになっているため、`state.js` に置いて `lifecycle.js` などから import する |
| P2 | 計算の形 | ゲージの毎時の増減は `pacedRate(1倍速の値)` = 値 × PACE(浮動小数のまま計算)。時間は `pacedMinutes(1倍速の分)` = 分 ÷ PACE を切り捨て、最低1分(§1.4 の MAX(n, 1))。切り捨てにすると §1.3 の表の値(うんち 5〜13分、3分ごと など)とちょうど一致する。そのぶん PACE=2 の孵化は 1.5分ではなく1分になる |
| P3 | PACE から計算するもの | ゲージ減衰・うんちがあるときの せいけつ 追加減衰・病気中の げんき 追加減衰・進化/孵化の時間(デモ速・リアル速とも)・うんちの出現時間・発病 (a) の判定間隔・発病 (b) のおなか0 継続時間・お別れの条件・おやつ上限のリセット間隔・ミニゲーム後の休憩(180秒 ÷ PACE、最低30秒) |
| P4 | PACE を掛けないもの | 年齢表示・セーブ時刻・昼夜判定(実時間)、オフライン補正の上限 24時間、演出の長さ、ミニゲーム1回の制限時間(もぐら 20秒・おんぷ 30秒) |
| P5 | 計算と保存の間隔 | 時間経過の計算の刻みと定期セーブを 1分 → 15秒 に短縮(§1.4)。減り方は経過時間から計算しているので、間隔を変えても結果は同じ |
| P6 | 確認用の切り替え | URL に `?pace=2` などを付けて開くと、その間だけ PACE を差し替えられる(§2 の5「PACE を 2 にしてリロード」の確認用)。保存はしないので、普通に開き直すと 3 に戻る |
| P7 | セーブ | 形式は version 2 のまま変更なし。ペースは保存しないので、既存のセーブは開くとそのまま3倍速で進む |

| PACE=3 のときの値 | デモ速 | リアル速 |
|---|---|---|
| ゲージ減衰/時(起きている) | おなか −24・きげん −15・せいけつ −12・げんき −18 | 同じ |
| ゲージ増減/時(寝ている) | おなか −9・きげん −6・せいけつ −3・げんき +36 | 同じ |
| 孵化 / ベビー→こども / こども→おとな | 1分 / 1時間 / 2時間 | 20分 / 8時間 / 16時間 |

| 発病 (a) / 発病 (b) | 3分ごとに15% / おなか0 が20分 | 同じ |
| 病気中の げんき 追加減衰 | −30/時 | 同じ |
| お別れ(おなか0 / きげん0) | 40分 / 8時間 | 400分(6時間40分)/ 8時間 |
| おやつ上限のリセット | 2時間ごと | 同じ |
